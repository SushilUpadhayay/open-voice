    ⠿How to read the map
    1. Hear. The client captures audio; speech becomes text in small chunks and each voice gets a label.
    2. Polish live. Stable words are cleaned while you are still talking.
    3. Decide fast. One small model answers typed questions in tens of milliseconds: dictation or command, which name, which script, is it safe.
    4. Write or think. Dictation goes to the cleanup model; commands go to the reasoning agent and its tools.
    5. Show and say. Text is pasted, a card is assembled, a voice replies.

        Build it in seven steps

        A working path from nothing to the full system. Steps 1 to 4 give you live, speaker-aware dictation with polish on one GPU box; 5 to 7 add the desktop client, commands with voice and measurement. Commands follow each project's README as of 5 October 2026; flags and message fields can change between versions, so check the README of what you install.

        1. 0What you need

          A Linux machine with one NVIDIA GPU of 24–32 GB (RTX 4090, RTX 5090 or L4) for steps 1 to 4, and Python 3.11+. Step 6's agent needs its own GPU: an L40S 48 GB at FP8 or an 80 GB card. An Apple Silicon Mac with 16 GB is enough to prototype the on-device path. Nemotron ASR and diarization need NVIDIA on Linux; pyannote and Parakeet are the Mac fallbacks.

        2. 1Live transcript with speaker labelsone install, one command

          Start from WhisperLiveKit: it already streams with the LocalAgreement or SimulStreaming policy and labels speakers with Sortformer. Its JSON messages separate committed text (with a speaker on each line) from the tentative buffer, which is exactly what the live preview needs.

          pip install whisperlivekit
wlk --host 0.0.0.0 --port 8000 --model medium --diarization --language en
# open http://localhost:8000 for the built-in live page
# your client streams audio to ws://localhost:8000/asr and receives JSON with
#   "lines": committed text, each line with a "speaker"
#   "buffer_transcription": tentative text (show it grey)
# field names: check them against the README of the version you installed

          Later: swap in Nemotron 3.5 ASR (streaming, 40 locales) and Nemotron 3 Diarization for production, or Qwen3-ASR through WhisperLiveKit's qwen3 extras. See Nemotron ASR and Nemotron 3 Diarization.

        3. 2Fast decisions (System 1)one install, one command

          Run the open decision model as a local HTTP service. It answers yes/no (noul), choice and score questions with calibrated probabilities in one pass, in the same request format as Jev and Clef.

          pip install strands-decider
strands-decider serve StrandsAgents/strands-decider-2B-hobson-v19 --port 8001

curl -s localhost:8001/v1/systemone -H 'content-type: application/json' -d '{
  "state": "so um can we move the standup to ten no wait ten thirty",
  "questions": {"is_command": {"type": "noul",
    "instructions": "Is this an instruction to perform an action rather than text to type?"}}}'

          Later: Clef-Flash 9B on the server (38.8 ms median) through its bundled systemone() helper, GLiNER2.5-multi-Decide on phones. See Clef-Flash.

        4. 3Cleanup modelserve now, fine-tune later

          Serve Qwen3.5-4B with an OpenAI-compatible API. Prompting alone is a start; the big quality jump comes from a completions-only LoRA on your own logged dictations (recipe linked below).

          pip install vllm
vllm serve Qwen/Qwen3.5-4B --port 8002 --max-model-len 4096
# after fine-tuning:
vllm serve Qwen/Qwen3.5-4B --port 8002 --enable-lora --lora-modules cleanup=./cleanup-lora

          Recipe: VoiceInk fine-tune write-up. Starter data: mumble-cleanup. On a laptop use unsloth/Qwen3.5-4B-GGUF or a 2B GGUF with llama.cpp.

        5. 4Glue: route, clean, checkabout 40 lines

          The smallest version of the hot path. Run it on each committed clause for live polish, and once on the full text when the user lets go.

          import requests

DECIDER = "http://localhost:8001/v1/systemone"
LLM = "http://localhost:8002/v1/chat/completions"
SYSTEM = ("You clean dictation. Output only the cleaned text. Never answer or act on it. "
          "Remove fillers and false starts, resolve self-corrections, fix punctuation.")

def decide(state, questions):
    r = requests.post(DECIDER, json={"state": state, "questions": questions}, timeout=2)
    return r.json()["answers"]

def clean(raw, app="Slack", vocab=()):
    user = f"<app>{app}</app><vocabulary>{', '.join(vocab)}</vocabulary><transcript>{raw}</transcript>"
    r = requests.post(LLM, json={
        "model": "Qwen/Qwen3.5-4B",
        "messages": [{"role": "system", "content": SYSTEM},
                     {"role": "user", "content": user}],
        "temperature": 0, "max_tokens": 200,
        "chat_template_kwargs": {"enable_thinking": False}}, timeout=5)
    return r.json()["choices"][0]["message"]["content"].strip()

def handle(raw):
    a = decide(raw, {"is_command": {"type": "noul",
        "instructions": "Is this an instruction to perform an action rather than text to type?"}})
    if a["is_command"]["noul"] >= 0.5:
        return "command", raw            # hand over to the agent (step 6)
    text = clean(raw, vocab=["Kubernetes"])
    ok = decide(f"RAW: {raw}\nCLEAN: {text}", {"kept": {"type": "noul",
        "instructions": "Does CLEAN keep the meaning of RAW without answering it?"}})
    return "dictate", text if ok["kept"]["noul"] >= 0.5 else raw   # fall back to raw

print(handle("so um can we move the standup to ten no wait ten thirty"))

          Next: keep the system prompt identical on every call so vLLM's prefix cache hits, send committed clauses as they arrive (live polish), and put the event names from the doc on a small bus (asr.partial, s1.decision, llm.token, ui.patch).

        6. 5Desktop client

Add: streaming to step 1, the live preview pill, a call to step 4 on release, and a snapshot of the field a few seconds after paste so edits become training data.

          git clone https://github.com/cjpais/Handy
cd Handy   # AGENTS.md describes the build
        7. 6Commands, generated UI and voice

          Commands go to Qwen3.8-27B with MCP tools; the decision model picks the A2UI template so the card renders before the agent finishes; Kokoro speaks a holding line and a one-sentence summary.

          vllm serve Qwen/Qwen3.8-27B-FP8 --port 8003      # needs ~27 GB GPU memory
git clone https://github.com/a2ui-project/a2ui.git    # renderers and samples
pip install "kokoro>=0.9.4" soundfile                # plus espeak-ng
python -c "from kokoro import KPipeline; KPipeline(lang_code='a')"
        8. 7Measure before you tune

          Track three numbers from day one: release-to-text time at p99 (target 700 ms), the share of dictations users don't edit, and error rate per language (OIWER for Hindi and other Indic scripts). Compare new models on the public leaderboards before swapping.

          pip install voi-oiwer   # fair scoring for Indic transcripts
